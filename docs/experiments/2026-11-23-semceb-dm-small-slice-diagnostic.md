## 1. 本轮要回答什么

本轮先用 Q63 的小切片检验“行级状态 → 双线性代理 → 配对预测”的完整关系，不直接开展全部 SemCEB 查询排名。

需要分开回答三件事：

1. **模型对齐**：Gemini Decision 1 对所有配对的判断总量，与官方参照基数有多大差距？
2. **表示能力**：少量行级语义状态及兼容矩阵，能否解释 DM 逐对判断之间的变化？
3. **统计与成本收益**：支付代理建设费用后，抽样或残差纠偏是否仍然划算？

候选假设是：可聚合状态能以记录级建设成本保留有用的配对关系，从而降低残差方差。但目前没有实验结论。总量相近可能来自误差抵消，不能替代配对诊断。

本轮使用 Q63、scale factor 10（sf10），作为开发诊断切片。Q63 的谓词、状态草案及官方总数已经在讨论中看过，因此不能把它称为未见测试查询。

## 3. 先冻结输入、方法和费用边界

在新增诊断请求前确认以下候选配置，并保存到独立运行清单：

| --- | --- |

约 130 次是请求量，不是美元预算或延迟承诺。choice 与 noul 的 token、耗时可能不同；当前价格未核实，工程中 USD 为 null。若需美元硬上限，必须先落实计价，再冻结预算。已有文件大小、mtime 和切片身份哈希不等于完整数据内容哈希，应在正式可复现实验前补足数据内容或已验证下载资产的校验记录。

本轮中的穷举矩阵属于**诊断资产**，不能成为估计器免费读取的 catalog。代理构建不读取官方真值或完整逐对矩阵。后续若依据诊断结果调整状态，记录新版本，并将收益视为开发结果；需要新的留出查询验证泛化。

## 4. 阶段 A：补齐 DM 配对矩阵

对 Q63 sf10 的全部 100 个有序配对调用同一 noul，沿用已有请求缓存。运行结束须验证：

- 恰有 100 个不同的 `(left_index, right_index)`，覆盖完整的 $10\times10$ 空间。
- 每个配对保留左右记录身份、概率、请求缓存键及响应；概率有限且在 $[0,1]$ 内。
- 输入、提示与模型配置一致；失败或缺失不作负例。
- 导出 $p_e$ 矩阵、$Y_e^{DM}$ 矩阵、软总量 $\sum_e p_e$、硬总量 $C_{DM}=\sum_eY_e^{DM}$。

在工程目录中，现有入口支持以下命令；这是冻结预算后才执行的步骤：

```bash
.venv/bin/python -m semceb_dm.runner \
  --query 63 --scale-factor 10 --method pair-sample \
  --samples 100 --seed 42 --max-requests 98 \
  --output ../../runs/semceb-dm/q63-sf10-dm-matrix-v1
```

该命令对全域无放回抽样，等价于穷举，只改变访问顺序。若已有两次缓存失效，98 次 HTTP 上限会使运行中止，不应静默提高预算。新运行目录不能覆盖旧产物。

与官方基数 52 的比较只能解释**总量差异**。没有官方配对标签时，无法计算相对官方的逐对准确率、precision 或 recall；总量相同也不能证明配对相同。

## 5. 阶段 B：构造并诊断状态聚合代理

按提前冻结的 Q63 配置运行代理：左侧 3 个状态、右侧 4 个状态；左右各 10 条记录分别调用 choice；12 个状态组合调用 noul 构造 $K$。

```bash
.venv/bin/python -m semceb_dm.runner \
  --query 63 --scale-factor 10 --method state-proxy \
  --state-config configs/q63-states.json --max-requests 32 \
  --output ../../runs/semceb-dm/q63-sf10-state-proxy-v1
```

形成 $\mu_e=\mathbf q_r^\top K\mathbf q_s$ 与代理和 $M$。本轮规模很小，可以在离线诊断中展开 100 对 $\mu_e$，检查求和结果与双线性聚合一致。正式估计器仍使用聚合式；诊断展开费用单独记录。

重点输出：

| 诊断 | 解释边界 |
| --- | --- |
| $M$ 对比官方基数与 $C_{DM}$ | 区分代理总量、DM 定义基数和官方参照总量 |
| $\mu_e$ 对比 $p_e$ 和 $Y_e^{DM}$ | 展示表示能否解释 DM 的配对变化；不代表官方配对正确率 |
| $S^2_{Y^{DM}-\mu}/S^2_{Y^{DM}}$ | 分母非零时判断固定 $\lambda=1$ 是否降低均匀抽样方差；分母为零时单独报告 |
| 协方差、相关性和幅度 | 正相关本身不足以保证残差方差降低 |
| 最大残差配对及其行状态、K | 定位粗状态碰撞、行级分类和兼容矩阵问题，保留负面例子 |
| 32 次建设的 token、耗时和缓存情况 | 全部为本查询建设费用，不能移入免费离线阶段 |

矩阵热图建议分别展示 DM 分数、硬判断、代理和残差。可按记录身份保持一致顺序；任何诊断排序都不能改变算法输入或配对权重。

## 6. 阶段 C：冻结矩阵上的离线抽样重放

该阶段需要补充分析脚本，目前工程尚未实现。脚本只读取已冻结产物，不调用 API；每次模拟向估计器暴露被抽中的标签，不暴露全域 $C_{DM}$ 或未抽中标签。

候选样本量为 $B\in\{2,5,10,20,40,60,80,100\}$，候选种子为 0–999。每个种子生成同一个配对随机排列，不同方法和样本量使用相应前缀，形成可配对比较。

比较三种输出：

1. **均匀抽样硬标签外推**：$\widehat C_{sample}=N\overline{Y^{DM}}$。
2. **纯代理**：$\widehat C_{proxy}=M$，不随主样本变化。
3. **固定系数残差纠偏**：$\widehat C_{res}=M+N\overline{(Y^{DM}-\mu)}$。

可以附带分析当前工程的软分数外推 $N\overline p$，但其直接估计对象为全域 DM 分数和，不与硬标签无偏结论混写。固定 $\lambda=1$ 的残差估计对冻结的 $C_{DM}$ 设计无偏，不对官方基数自动无偏。

按两个目标分别报告：

- **相对 $C_{DM}$**：经验偏差、方差、RMSE、Q-error 中位数和高分位，以及全零样本和负估计出现频率。非截断原始估计用于核查统计性质。
- **相对官方基数**：相同输出的 clamped Q-error，展示 DM 与官方参照的偏差如何影响最终评测。不要将这种偏差解释为抽样失败。

全域普查时，普通抽样与残差估计都应返回 $C_{DM}$；这是分析脚本的必需正确性检查。即使 DM 与官方不一致，也不能按官方总数反调阈值、状态或系数来消除误差。

基于完整矩阵求得的最优控制系数仅可作为标注清楚的诊断上限，不计入主方法。独立先导拟合、分层或重要性抽样暂不同时加入，避免无法判断收益来源。

## 7. 成本比较必须同时给出两个视角

**固定主样本量：** 各抽样方法使用相同配对和 $B$，比较残差方差。这解释统计效率，不能直接说明总成本更低。

**固定逻辑请求预算：** 代理方案先支付 32 次建设请求，再用剩余请求取得主标签；均匀抽样将预算用于配对判断。例如总预算 42 次时，应比较“32 次建设＋10 对标签”和“42 对标签”。在本轮自连接中是否复用更多行表示，必须符合左右问题语义，不能仅因同表就默认省掉一侧。

请求数不是统一费用单位。另行报告实际建设与逐对调用的 token、时间；根据观测成本重建的费用曲线必须标为重放估算。读取矩阵缓存只需本地时间，不能据此声称线上参照调用免费或取得了实际端到端加速。所有方法获得相同缓存待遇。

100 对的穷举只用于建立诊断对象，单列其真实开销。首次联通耗时也不能替代大规模运行的延迟估计。

## 8. 何时继续扩大，何时先修方法

| 观察结果 | 下一步 |
| --- | --- |
| DM 完整基数与官方相差明显 | 先研究模型与提示语义差异；没有官方配对标签时，不把残差纠偏当作对齐解决方案 |
| 代理总量接近但残差方差很高 | 检查误差抵消；代理未必适合作控制变量 |
| 代理几乎恒定，或大量记录落入 other | 检查状态表达是否不足；常数代理不会提供方差收益 |
| 固定 $\lambda=1$ 增加方差 | 诚实报告，随后单独设计独立先导系数选择；不能事后用全矩阵最优系数替换主结果 |
| 统计方差下降但建设费用不划算 | 研究表示复用、规模效应或更低建设成本，先不宣称系统收益 |
| 关系表示有预测力且成本可接受 | 再提议 sf100 和新查询上的预算实验，验证扩大后收益是否持续 |

sf100 上，同一状态数的建设约为 $100+100+12=212$ 次请求，而配对总体为 10,000。这个数量级差异不是性能证明：普通抽样也可能只需很少标签。扩大前仍需重新确认总预算和比较设置。

Q64 的等级关系应另设表示；Q87 的适配关系也不能直接沿用 Q63 的材料—工具状态。未参与状态或提示开发的查询应在后续阶段作为留出集固定，开发结果与留出结果分开报告。
