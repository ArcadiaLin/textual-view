# SemCEB：任务、数据范围、参考答案与 baseline 的认识澄清

日期：2026-11-24。性质：讨论记录，不是新实验协议或研究结论。

本记录整理 Q63 小切片诊断之后的讨论，重点澄清“benchmark 要我们输出什么”“每道查询使用什么数据”“官方成立数代表什么”。本次没有启动新的模型实验。

证据基于本地论文 [source.md](../../../references/papers/2026-SemCEB/source.md) 和官方仓库 [utndatasystems/SemCEB](https://github.com/utndatasystems/SemCEB)，核验版本为 `fec6bde7d1b23fc751f8701872fafda777a63942`。2026-11-24 通过 GitHub API 核对的远端 main 与此版本一致。以下事实描述以该版本为限。

## 1. SemCEB 评测的是数量估计，而非找出全部匹配记录

Semantic Filter 与 Semantic Join 是两类任务，不是两个评价指标。SemCEB 要求估计语义算子的输出行数，不要求估计器返回全部匹配记录或配对。

| 方面 | Semantic Filter | Semantic Join |
| --- | --- | --- |
| 判断对象 | 单条记录 $r$ | 有方向的记录对 $(r,s)$ |
| 谓词 | $P(r)$ | $P(r,s)$ |
| 候选范围 | $n$ 条输入记录 | $n\times m$ 个候选配对 |
| 估计目标 | 成立记录数 | 成立配对数 |
| 选择率 | 成立记录数除以 $n$ | 成立配对数除以 $nm$ |

例如，可以只判断一小部分配对，然后外推总数；也可以通过离线统计或其他代理估计数量。先穷举所有配对不是 benchmark 的要求。

公开工作负载共 102 道查询：62 道过滤、40 道连接。过滤包括 30 道商品文本过滤、13 道商品图像过滤、19 道评论文本过滤；连接包括 20 道商品自连接、18 道商品与评论连接、2 道评论自连接。

## 2. 数据组织：共享数据表、固定切片、多条查询

SemCEB 并不是为每道 Q 单独准备一组配对。基本结构是：

> 共享数据表 → 按配置确定数据切片 → 查询指定表、字段和语义条件 → 在该范围上估计结果数量。

本地 `products_filtered_with_embeddings.parquet` 经读取 Parquet 元数据核实，共有 **45,693 条商品记录**。这指 SemCEB 提供的处理后商品表，不是原始 Amazon 数据全集。

官方 [DataLoader](../../../references/repos/SemCEB/src/semceb/data/loader.py) 使用固定随机种子 42 打乱商品行，再按规模取前若干行。相同数据与加载规则下，sf10 对应固定的 10 件商品，sf100 对应同一排列的前 100 件。它们不是为 Q63 特意筛选的材料或工具。

| 商品规模 | 商品自连接候选有序配对数 | 含义 |
| --- | ---: | --- |
| sf10 | 100 | 10 件商品与自身表连接 |
| sf100 | 10,000 | 100 件商品与自身表连接 |
| 全部 45,693 件 | 约 20.88 亿 | 全表自连接；本轮没有执行 |

Q63、Q64、Q87 在相同商品切片上做自连接时使用相同的候选范围，改变的是谓词或引用字段。Q63 讨论材料与工具的关系，Q64 比较描述的详细和具体程度，Q87 讨论耗材与适配商品的关系。

注意：规模参数不能理解为每张表都恰好有这么多行。相关评论表由加载规则随商品范围筛选。官方配置还区分过滤用的 `scale_factor` 与连接用的 `join_scale_factor`；论文主要比较过滤 sf1000、连接 sf100。

## 3. Q63 的 52 与 4,239 分别对应什么

Q63 的英文条件是：

> The first product primarily provides crafting materials and the second product primarily provides tools that could be used with those materials.

该查询读取左右商品的 `description_json`。以下值通过完整查询缓存键核对，来自官方基数缓存，不是按比例推算：

| 数据范围 | 候选配对 | 官方成立数 | 选择率 |
| --- | ---: | ---: | ---: |
| Q63 sf10 | 100 | **52** | 52% |
| Q63 sf100 | 10,000 | **4,239** | 42.39% |

两者参考模型均为缓存中记录的 `gpt-5.4-nano`。参考答案属于“查询 + 数据范围 + 模型 + 提示”的组合，不是 Q63 在所有规模上的固定答案。

本轮 DM 诊断只做了 **一道查询 Q63、一个 sf10 切片**。100 指候选配对数量，不是题目数量。按当前 DM 提示及分数阈值 0.5，100 对中有 **5 对**判成立；分数总和约 17.658；状态代理估计约 39.037。

完整判断 100 对，是为检查代理与抽样机制而做的小规模普查。后续 1,000 个随机种子的抽样重放复用了这些判断，没有增加新查询或重新调用模型。详见[诊断结果](2026-11-23-semceb-dm-small-slice-diagnostic-results.md)。

## 4. 官方如何判定“成立”

论文明确把参考真值定义为指定模型与提示执行语义算子所得到的数量，而不是人工标注的客观真值。

官方配置要求模型根据给定上下文判断陈述，按 `Answer: True` 或 `Answer: False` 输出。Q63 提供原查询条件及两条商品描述；代码通过 LOTUS `sem_join` 执行连接，统计返回结果的行数并缓存。论文说明连接真值使用嵌套循环计算，避免近似连接优化改变结果。

证据：[官方配置](../../../references/repos/SemCEB/config.toml)、[LotusBackend](../../../references/repos/SemCEB/src/semceb/llm_backends/lotus_backend.py)、论文任务定义与实现部分。这里描述的是公开协议和代码；没有拿到当时生成 Q63 缓存的全部原始模型响应，不能逐条审计那次运行。

目前未发现额外的人工标注手册来规定“蜡笔属于材料还是工具”“收纳包是否属于可用于材料的工具”“信息不足时如何处理”等细节；这些边界主要由查询自然语言、提示与模型共同决定。

因此，52 与 DM 的 5 不一致，能确认阳性总量不同，但不能据此认定 DM 错误，也不能确认两者只是判断松紧不同。没有逐对参照，就不知道 DM 的阳性是否包含在官方阳性中。

## 5. 官方公开了哪些标签，哪些尚未找到

| 资产 | 当前核实内容 | 能否用于 Q63 逐对核对 |
| --- | --- | --- |
| `benchmark_queries/ground_truth_cache_*.json` | 基数与选择率；sf10、sf100 包含连接查询 | 不能，只能核对总数 |
| `results/raw/query_results/` | 124 个 Parquet，对应 62 道过滤查询在 sf1000、sf10000 上的结果 | 不能，当前没有连接结果文件 |
| 论文发布说明 | 说明提供预计算基数，链接到官方代码仓库 | 没有给出额外连接标签下载入口 |

通过完整远端仓库文件树再次核实，当前公开结果目录没有 Q63 的匹配对文件。官方数据存储桶的目录列举返回 HTTP 403，因此只能说**未找到公开下载入口**，不能断言作者没有保存其他资产。

获取具体匹配对的候选方式：向作者索取原运行结果；或使用官方执行流程自行复现并保存。后一种应标为自行复现的参考标签，不能保证重新执行恰好仍得到 52，也不能冒充原缓存对应的逐对标签。本轮没有发出联系请求或启动参考模型调用。

讨论中的评价是：SemCEB 已提供数量估计核心评分所需的参照，但公开的连接逐对结果与执行证据不足以支持完整的分歧诊断。语义模型重跑有成本、结果可能变化，因此仅提供总数的局限比传统确定性 SQL 更明显。该评价不等于认定 benchmark 无效。

## 6. 为什么人工审核时商品描述看起来奇怪

商品表的一行代表商品记录，但审核材料仅展示 Q63 实际读取的 `description_json`，不是整行商品信息。该字段是以 JSON 表示的描述片段列表；商品标识如 `B0BFW3YZDS` 不是商品名称。

| 编号 | 根据描述作的辅助概括（非原始标题） | 信息特点 |
| --- | --- | --- |
| 0 | 绘画套装 | 只有 `Drawing Kit`，组成不明 |
| 1 | 双头马克笔 | 描述较完整 |
| 2 | 透光描图板 | 包含用途、规格与配件 |
| 3 | 拼豆材料套装 | 描述较明确 |
| 4 | 丝带、包装材料 | 更像品牌介绍 |
| 5 | 纸艺切割模具 | 有拼写和格式问题 |
| 6 | 玻璃及灯工相关商品 | 商家宣传为主，具体商品不明 |
| 7 | 手工用品收纳包 | 英文表达较生硬 |
| 8 | Crayola 蜡笔 | 描述较完整 |
| 9 | 绘画画笔套装 | 较长营销描述 |

另一个问题来自导出展示：Markdown 中 `<pre>` 内的 `&quot;`、`&#x27;`、`&amp;` 是导出器添加的 HTML 转义，分别对应双引号、单引号、与号；不是模型输入被替换成了这些实体。直接阅读源码不方便。讨论提出可将 JSON 片段拆成段落改善阅读，但本记录不表示已完成这项修改。

曾生成的人工审核表（`2026-11-24-q63-sf10-human-review.md`，当前目录中未保留该文件）包含：10 件商品原文、全部 100 个候选配对、人工判断栏与折叠 DM 分数。它不是“官方成立的 52 对清单”。审核时允许保留不确定；若额外查看标题、图片等信息，应与仅依据查询指定字段的判断分开记录。

## 7. 两类任务如何评分

两类任务使用相同的核心估计精度指标。设官方结果数量为 $c$，方法输出为 $\hat c$：

$$
Q=\max\left(\frac{\max(\hat c,1)}{\max(c,1)},\frac{\max(c,1)}{\max(\hat c,1)}\right).
$$

Q-error 越接近 1 越好。Q63 sf10 中估计 39 对对应约 1.33，估计 5 对对应 10.4。评分比较数量，不是逐对 Precision、Recall 或分类准确率；数量正确不能证明匹配身份正确。

其他维度包括在线估计 API 费用、调用数与 token、估计延迟、辅助元数据的内存/存储开销，以及支持的查询覆盖率。正式比较应保持数据、目标模型语义和预算口径一致。

## 8. 论文 baseline 及其与本轮实验的差别

| 方法 | 思路 | Filter | Join |
| --- | --- | --- | --- |
| 均匀抽样外推，1%、5%、10%、15%、20% | 对抽样表执行语义算子，再外推全表数量 | 支持 | 支持 |
| Semantic Histograms 的适配实现 | 使用 KV-cache 扫描等机制估计 | 只覆盖 31 道单列过滤 | 不支持 |

官方抽样连接的实现是**抽基表记录后连接样本表**。商品自连接左右使用同一份表样本。例如 sf100 下取 5 件商品，产生 25 个候选样本配对；若其中 10 对成立，则外推为 $10{,}000\times10/25=4{,}000$。这里的 10 是说明算法的假设数字，不是实际测量。

本轮诊断 baseline 是**直接均匀抽候选配对**。两种抽样设计不同，不应互换名称或把本轮胜负描述为对官方 baseline 的胜负。正式比较需要原样保留官方行为；自连接同样本还涉及对角线与非对角线配对不同的纳入概率，不能把它直接视为独立的均匀配对抽样。

论文报告的结果与限制：

- 5% 抽样在其测试数据上已相对准确，但较小规模不足以推出普适的最低抽样比例。
- 在线模型调用导致抽样费用与延迟明显，连接任务尤其突出。
- Semantic Histograms 的误差总体高于甚至 1% 抽样；平均估计约 6 秒，1% 抽样约 5 秒，并有 KV-cache 开销。该实现没有 KV-cache 压缩，也未评测原方法的 Specificity Model 和 ensemble，不能把结果概括为原方法所有版本的能力。
- SemStats 因作者写作时未获得实现，没有纳入该比较。

证据：[论文 §4](../../../references/papers/2026-SemCEB/source.md)、[官方抽样实现](../../../references/repos/SemCEB/src/semceb/algorithms/extrapolated_sampling.py)。

## 9. 对后续研究的当前含义

以下是讨论形成的边界理解，不是已批准的新实验：

1. 面向 SemCEB 的任务是低成本估计参考模型的结果数量；DM 不必先返回所有匹配对。
2. 若抽样标签全部来自 DM，估计会趋向 DM 自己的判定总量，而不自动趋向官方缓存总量。要分别讨论 DM 判别语义与估计机制的误差。
3. Q63 sf10 是已经查看过结果的开发诊断切片，不能当作未见测试集。
4. 人工审核可以检查查询歧义、证据不足和模型判断的合理性，但不能恢复未公开的官方逐对标签。
5. 需要补充官方逐对结果、复现参考执行，或扩大到 sf100 时，应先明确目的、目标模型、预算和比较方法，再冻结配置。本文没有启动这些步骤。
