# Paper Close Read

## 精读目标

把一篇论文的研究故事讲清楚：作者为什么认为这个问题值得做，如何从问题走到设计，
最终增加了什么知识或能力。读者应能理解设计选择之间的因果关系，并判断贡献成立的范围。

默认聚焦单篇论文。相关工作只补充理解问题与贡献所必需的背景，不主动扩展成文献综述。

## 产物与材料

默认保留两项产物：

- `source.<ext>`：原始材料副本。arXiv 为 `source.md`，PDF 为 `source.pdf`，
  已有文本保留原扩展名。
- `analysis.md`：连贯的精读笔记，默认使用用户当前语言，不明确时用中文。

按材料来源保留 `paper.txt`、`images/` 和图片索引等辅助材料。
不要求独立的证据地图、claim 映射表或写作前置文件；关键证据直接融入正文。

在本项目中，工作目录默认是 `references/papers/<年份>-<主题>/`，如
`references/papers/2024-ExpeL/`。年份取发表年份，未发表时用 arXiv 版本年份；
主题用方法名、系统名或简短关键词，不带作者姓氏。用户指定的位置优先。

### 准备原文

以下命令的脚本路径相对于本 skill 目录；可以从仓库根目录使用完整路径调用。

- **arXiv ID / URL**：先读 [arxiv-md-workflow.md](references/arxiv-md-workflow.md)，
  运行 `bash scripts/prepare_arxiv_md.sh <arxiv-id-or-url> <output-dir>/`。
  wrapper 通过 uv 调用仓库的 `packages/arxiv2md`，下载 Markdown 与可获取的图片。
  需安装 uv，首次运行可能下载依赖。
- **本地 PDF**：先读 [local-paper-workflow.md](references/local-paper-workflow.md)，
  运行 `uv run scripts/prepare_local_pdf.py <paper.pdf> <output-dir>/`。
  脚本声明 PyMuPDF 依赖，复制原文、提取带页码的文本并渲染页面。
- **已有文本 / Markdown / 截图等**：直接整理原文和附带图片，不重复提取。

阅读全文中与核心论证有关的部分，包括必要的附录。材料缺图、缺表、缺附录或提取不可靠时，
在正文相关位置说明影响。

## 以研究叙事组织精读

下面三个问题是理解和写作的主线，不是必须照抄的章节名或固定顺序。
根据论文类型、真正的贡献和用户关注点决定篇幅与组织方式。

### 为什么要做

解释问题出现的具体场景，谁受到什么约束，解决后有什么价值。
讲清已有方法能做到什么、在哪个条件下遇到瓶颈，以及作者抓住的缺口是什么。
避免只复述“领域很重要、现有工作不足”；尽量用论文中的例子或失败情形说明矛盾。

将问题设定和作者的关键观察连起来：为什么这个观察会导向后面的方案？
指出假设与适用条件，区分论文提供的事实和作者对研究动机的判断。

### 怎么做

先说明核心想法，再围绕它解释方法如何工作，以及关键设计为何需要。
沿实际流程、一个贯穿例子或论证过程展开，把输入、输出、模块之间的关系讲清楚。
不要把方法写成互不相干的模块清单，也不要逐节翻译原文。

公式只展开理解机制所需的部分：符号表示什么、约束或目标改变了什么、与问题瓶颈有什么关系。
保留原论文的符号语义，使用 `$...$` 和单独成行的 `$$` 排版。

适配论文类型：理论论文解释假设、关键推理和定理含义；实证论文解释样本、变量和识别思路；
系统论文解释接口、机制和取舍。论文没有实验时，不强行套用实验分析。

### 贡献了什么

将作者声称的贡献与实际论证或验证支持的贡献区分开。
相对最相关的已有方法，究竟新增了什么机制、能力、解释、结论或观察？
为什么这个增量有价值，哪些部分是已有技术的组合或依赖额外条件？

让验证服务于这个判断：挑出决定性的比较、消融、证明或案例，说明它在回答哪个问题，
结果如何支持核心想法，以及还有哪些替代解释或未被验证的范围。
定量结论带上必要的设置、比较对象和关键数字，避免只写“明显提升”。
实验复杂时可按需读 [experiment-analysis.md](references/experiment-analysis.md)，
其中的问题用于检查论证，不规定输出章节。

局限要落到贡献边界：什么前提变化后可能失效，论文没有回答什么，哪些结论仍是猜测。
如有用户明确的研究背景，再说明可借鉴之处，不虚构与本项目的关联。

## 写作方式

- 开头尽快交代论文在什么问题上，用什么核心想法，取得了什么贡献；保留标题与可追溯的来源。
- 用连贯段落和有解释力的小标题推进论述，标题、数量、顺序和篇幅由内容决定。
  不要求固定 frontmatter、摘要全文或翻译、贡献评分、核心证据表、未来工作等栏目。
- 将动机、设计选择和贡献连接起来，避免把论文压缩成问答清单或把摘要扩写一遍。
- 深度放在决定论文价值的细节上；不要求每个模块、实验或附录平均展开。
- 选择能帮助解释机制和贡献的原论文图表，放在相关段落旁并解释读法及其意义。
  不设方法图或结果图的数量配额，也不要求逐一交代未采用的图表。
- 图片使用真实文件名和相对路径。PDF 页码以提取文本的页码标记为准；
  arXiv Markdown 用章节锚点、图号、表号或公式编号定位，不编造页码。
- 关键判断与数字在相关段落就近注明来源；区分作者声称、原文支持的结果与自己的解释。
  保留不确定性，图文提取缺失时不要猜测。

## 交付前检查

检查读者能否复述论文为什么做、关键想法怎样解决问题、实际贡献及其边界。
核对关键数字、符号、来源和图片是否准确，尤其是自己的解释有没有超出论文证据。
检查叙事是否连贯、细节是否有助于理解；不为填满模板补写空泛章节。
